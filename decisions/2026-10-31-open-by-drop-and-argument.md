# Opening a project by dropping it, or naming it on the command line

A `.notebook` dropped on the window opens, asking to save first as Open Project… does, instead of being added as a page (`Dropping` in `crates/app/src/ingest.rs`, the one rule both the drop and the overlay follow). Other files dropped with it are left out, with a hint saying so; two or more projects open none, with an error; a project dropped while a dialog is asking is ignored. While files are dragged over the window, the overlay (or the empty window's title) says what dropping them will do, using the paths macOS gives during the drag; the overlay is a label on a foreground layer, not painted text or an `Area` (hidden on its first frame), so it's in the accessibility tree.

`notebook-tools path/to/notes.notebook` starts with the project open (`crates/app/src/cli.rs`), for agents and scripts driving the app. Anything else on the command line, or a project that can't be opened, is an error in the terminal with exit code 2, before the window opens; photos missing from the project are reported in the window as when opening it. Reason: Human Taste (leaving other files out, refusing several projects, terminal errors, the overlay text); unquestioned agent recommendation for ignoring drops while asking and the overlay as a label.
