# Claude API key in the OS keychain, entered in the app

Anthropic doesn't let third-party apps sign in with Claude.ai (Free/Pro/Max) or register OAuth clients, so users bring a Claude Console API key. Transcribing without credentials, or Enter Key… in Settings, opens a dialog linking to the Console's keys page. The pasted key is checked with `GET /v1/models` (free): a 401/403 isn't saved; a network or other error saves it with a warning. Saved keys go in the OS keychain (`keyring`, service `net.ftamp.notebook-tools`, the future bundle id); Settings shows the key masked, and Remove asks first. Switching to the Transcribed view doesn't ask for a key; only Transcribe, Transcribe All and Force Retranscribe do.

`ANTHROPIC_API_KEY`, then `ANTHROPIC_AUTH_TOKEN`, win over the keychain, which isn't read at launch while either is set: unsigned dev builds change every build, so macOS asks for keychain access each time (checked 2026-11-15: launch blocks on the prompt). Without them it must be read at launch, to know whether pages can be sent, so dev runs pass the debug-only `--no-keychain` (`scripts/run.sh` does). Reading the keychain doubles as checking there is one; without one (e.g. Linux without a Secret Service) the dialog says to set `ANTHROPIC_API_KEY`, and nothing is written to disk. `ant`'s login comes after the keychain: `2026-11-15-ant-login-fallback.md`. Reason: Human Taste (keychain, env first, the service id, technical friends as the audience); unquestioned agent recommendation for the rest.
