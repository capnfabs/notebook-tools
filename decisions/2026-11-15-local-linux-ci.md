# Local Linux CI in apple/container

`scripts/check.sh` ends by running `scripts/check-linux.sh`, which runs clippy and the tests on arm64 Linux (Debian trixie, for libheif ≥ 1.19) in an apple/container VM, so the libheif decoder that macOS never compiles is built and its HEIC tests run. Format and image checks don't depend on the platform, so they run only on the Mac. There's no hosted CI. The image comes from `scripts/linux/Containerfile` and is rebuilt only when it or `rust-toolchain.toml` changes. That file pins one Rust for both, so clippy agrees. Builds are cached in named container volumes (the target one per lockfile and toolchain: `2026-11-18-linux-target-volume-per-lockfile.md`), and the source is mounted read-only with `--locked`. If container is missing or stopped, the step fails and says how to fix it. `--mac-only` skips it while iterating. The first run took about 7 minutes and a warm one about 15 seconds. The image guardrails' "no CI copy" (`2026-11-01-image-guardrails.md`) still holds.

Reason: Human Taste (Linux only, apple/container over Docker, local only, on by default with `--mac-only`, failing when container isn't there); unquestioned agent recommendation (arm64, clippy + tests, the toolchain pin, volumes, running after the Mac steps).
