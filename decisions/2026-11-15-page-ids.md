# Pages are told apart by a `PageId`, not their names

Each `Page` gets a `PageId` (`notebook_core::page`), a counter unique while the app runs. Selection, load and transcription jobs, textures, corner placing, dialogs and the transcript view all use it, and names can repeat: two `IMG_0001.jpg`s from different folders are two pages. The ID isn't saved. The project file is unchanged and `PROJECT_VERSION` stays 1, though an older build opening a project with repeated names keeps only the first page of each name. Pages with the same name keep their order among themselves: a new one goes after them, and Sort by Name is stable. Names are shown as they are, with no folder or number added. The eval log groups corrections by ID and logs it on every line (`id=3`), which only means something within a session.

A photo whose SHA-256 is already a page's is left out silently, whatever its name. If pages are missing that photo (`2026-11-15-missing-pages-shown.md`), it fills them in instead: they keep their ID, corners and transcript, take its name and path, load, and are selected, with "Found the photo for …" in the status line. That's an unsaved change. Reason: Human Taste (skip by hash, filling in, the name following the file, no disambiguation, stable ties, logging the ID, no version bump); unquestioned agent recommendation for per-session IDs rather than saved UUIDs, and a process-wide counter so leftover jobs from a closed project can't land on a new page.
