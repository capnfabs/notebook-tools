# User-facing text lives in one Fluent file

Everything the app says to the user is in `crates/app/i18n/en-US/notebook_app.ftl`, looked up with `t!` (`crates/app/src/i18n.rs`, wrapping `fl!` from `i18n-embed-fl`, as in egui discussion #1751), which checks message ids and arguments at compile time. Each sentence is one message, with Fluent selectors for plurals, so it can be reworded or translated whole. Commands' labels are messages too (`Command::label`), and buttons that do a command use its label, in its Title Case. Errors from `notebook_core` are worded by the app from their variants (`i18n::ocr_error` and friends); core's `Display` stays for logs. UI tests find widgets through the same messages, so rewording never breaks them. `every_message_is_used` keeps the file free of dead text. Out of scope: logs, text written into exported files, the date format, and macOS's own menu items. Only English is loaded; a language would be another `i18n/<lang>/notebook_app.ftl` plus picking it.

Reason: Human Taste (one place to revise copy, i18n-ready, Fluent over a Rust strings module, tests using the lookup, core errors worded by the app). The runtime cost, a lookup per string per frame, was judged negligible.
