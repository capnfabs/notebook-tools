# Relinking a page to its photo: by hash, else by every EXIF ID, and only to the same shape

Each photo's upright pixel size (required) and EXIF IDs (PhotoIdentifier from Apple's MakerNote, ImageUniqueID, DateTimeOriginal, SubSecTimeOriginal, OffsetTimeOriginal; optional) are read from its header when it's added (`notebook_core::photo_meta`, `kamadak-exif` on every platform plus our own MakerNote parser) and saved in the project, still `PROJECT_VERSION` 1: projects saved without sizes no longer open. A file is a page's photo if its SHA-256 is the same; it looks like it if every one of those EXIF IDs is equal (missing on both counts as equal) and at least a PhotoIdentifier, ImageUniqueID or DateTimeOriginal is there; the filename never decides. Relink… (Page menu and the placeholder, opening in the old folder or its nearest parent left) and Use Changed File (a photo changed in place) relink a same-hash file at once, and ask first otherwise: "looks like the same photo" for an EXIF match, a warning with Relink Anyway for none. A dropped file that's a missing page's by hash fills it in without asking, as before; one that only matches by EXIF asks Relink / Add as New Page / Cancel, picking among several pages with radio buttons. Cancel (Cancel All when more would follow) stops the questions, leaving out the files still to be asked about; everything unambiguous in the drop has already been added. No two pages share a photo: a file that's another page's is refused.

A file of another aspect ratio or orientation is never relinked: Relink… refuses with both sizes, and a drop adds it as a new page with a hint. Corners and transcript boxes can't be mapped onto a crop or a turn, so a PDF's text layer would be wrong, and a missing page still exports to Markdown from its saved transcript, so refusing loses nothing. The same shape at another size scales the page's corners and its transcript's crop (the boxes are in the sent image's pixels, so they stay), and the dialogs (asking, and refusing another shape) compare the two photos in a table, field by field, mismatches in red. Reason: Human Taste (all-EXIF equivalence, required size and no version bump, refusing other shapes, drop questions and Cancel All, one page per hash, only the chosen page relinked); the comparison table and keeping Add as New Page bottom-left; unquestioned agent recommendation for `kamadak-exif` everywhere and the Page menu commands.
