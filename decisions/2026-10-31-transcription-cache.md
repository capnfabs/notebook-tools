# Transcription cache: raw responses by photo hash, version and model

Claude's raw responses are cached in the OS cache directory (`~/Library/Caches/notebook-tools/transcriptions`), one formatted JSON file per photo and model, `{sha256 of the file}-v{CACHE_VERSION}-{opus|sonnet}.json`, with the size of the image sent and the corners it was cropped to (`2026-10-30-boxes-follow-corners.md`). Lookups prefer the selected model's entry and fall back to the other's, so a cached page isn't sent again unless forced. Entries are parsed on load like a live response, so parsing changes need no bump; failures aren't cached. A schema change must bump `CACHE_VERSION`, since old answers won't parse (a test fingerprints the schema); prompt, model or send-image changes bump it only if the pages should be redone, since that re-pays for every page. `notebook-tools --clear-caches-only` (run by `scripts/clear-cache.sh`) or Settings deletes the lot (`2026-11-01-manual-cache-clearing.md`).

Entries from older versions are kept until the user clears the cache, so builds sharing it don't throw away what another paid for (`2026-11-01-manual-cache-clearing.md`). Without credentials the cache still opens, so cached transcripts can be viewed, corrected and exported, while Transcribe, Transcribe All and Force ask for an API key (`2026-11-15-api-key-in-keychain.md`); only without a cache directory as well are the Transcribed view and export disabled. Reason: Human Taste (key, bump rule, credentials-free use); agent recommendation accepted for the rest.
