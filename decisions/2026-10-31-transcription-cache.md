# Transcription cache: raw responses by photo hash, version and model

Claude's raw responses are cached in the OS cache directory (`~/Library/Caches/notebook-tools/transcriptions`), one formatted JSON file per photo and model, `{sha256 of the file}-v{CACHE_VERSION}-{opus|sonnet}.json`, with the size of the image sent and the corners it was cropped to (`2026-10-30-boxes-follow-corners.md`). Lookups prefer the selected model's entry and fall back to the other's, so a cached page isn't sent again unless forced. Entries are parsed on load like a live response, so parsing changes need no bump; failures aren't cached. A schema change must bump `CACHE_VERSION`, since old answers won't parse (a test fingerprints the schema); prompt, model or send-image changes bump it only if the pages should be redone, since that re-pays for every page. `scripts/clear-cache.sh` deletes the lot.

On startup the app prunes entries from older versions on a background thread; newer versions' are kept, so running an older build doesn't throw away what a newer one paid for, and files that aren't entries are left alone. Without credentials the cache still opens, so cached transcripts can be viewed, corrected and exported, while Transcribe, Transcribe All and Force stay disabled with a hint; only without a cache directory as well are the Transcribed view and export disabled. Reason: Human Taste (key, bump rule, when to prune, credentials-free use); agent recommendation accepted for the rest.
